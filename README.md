# 충전함 점검 — 설치 안내 (구글 앱스 스크립트)

학교 구글 계정으로 로그인하고, 당번 학생만 보관함 사진을 올려 코인을 받는 점검 앱입니다.
기록과 코인은 선생님의 구글 시트에 쌓입니다.

## 파일
| 파일 | 역할 |
|---|---|
| `Code.gs` | 서버 코드 (로그인 확인, 사진 분석, 코인 지급, 시트 기록) |
| `Index.html` | 학생·선생님 화면 |
| `appsscript.json` | 배포 설정 (학교 도메인 사용자만 접근) |

## 설치 순서 (약 15분)

### 1. 시트와 스크립트 만들기
1. 선생님 학교 구글 계정으로 새 구글 시트를 만듭니다. 이름은 `충전함 점검`처럼 정합니다.
2. 메뉴 **확장 프로그램 → Apps Script**를 엽니다.
3. 기본 `코드.gs`의 내용을 지우고 `Code.gs` 내용을 붙여 넣습니다.
4. 왼쪽 **+ → HTML**을 눌러 이름을 `Index`로 만들고, `Index.html` 내용을 붙여 넣습니다.
5. 왼쪽 톱니바퀴(프로젝트 설정)에서 **"appsscript.json 매니페스트 파일 표시"** 를 체크합니다. 편집기에 나타난 `appsscript.json`의 내용을 이 폴더의 `appsscript.json`으로 바꿉니다.

### 보관함 구조 (코드에 들어 있는 기본값)
이 앱은 **3단 선반, 한 단에 11칸, 모두 33칸**인 보관함을 기준으로 만들었습니다. 각 단 위쪽 띠에 LED가 한 줄로 있고 LED 아래에 칸 번호(1~11, 12~22, 23~33)가 인쇄된 구조입니다.
칸 상태는 **크롬북이 있는지**와 **LED 색**을 따로 판정해서 정합니다. LED는 충전기가 연결됐는지만 알려 줄 뿐 크롬북이 있는지는 알려 주지 않기 때문입니다.

| 크롬북 | LED | 앱의 판정 | 사유 입력 |
|---|---|---|---|
| 있음 | 초록 | 충전 완료 | 필요 없음 |
| 있음 | 빨강 | 충전 중 | 필요 없음 |
| 있음 | 꺼짐 | **충전 안 됨** (충전기가 연결되지 않음) | 필요 없음 |
| 없음 | 꺼짐 | **비어 있음** | **필요함** |
| 없음 | 켜짐 | 켜진 LED를 따르되 `?`로 표시해 확인 | 필요 없음 |

칸 수나 한 단의 칸 수가 다른 보관함이면 `Code.gs` 위쪽 `CONFIG`의 `SLOTS`와 `COLS`를 고치세요.
사진은 보관함 정면에서, LED 띠 세 줄이 모두 보이게 찍어 주세요. LED가 작아서 흐리거나 멀리서 찍으면 읽기 어렵습니다.

### 2. 시트 준비
1. 편집기 위쪽 함수 목록에서 **setup**을 골라 **실행**합니다. 권한을 묻는 창이 뜨면 허용합니다.
2. 시트에 탭 5개가 생깁니다.
   - **보관함**: 반마다 보관함 이름과 **사용하는 칸 수**를 적습니다.
   - **학생**: 이메일, 이름, 당번(당번인 학생만 `O`), **반**, 번호
   - **교사**: 선생님 이메일
   - **점검기록**, **코인내역**: 앱이 자동으로 채웁니다. 직접 고치지 않습니다.
3. **보관함** 탭에 반마다 한 줄씩 적습니다.

   | 보관함(반) | 사용하는 칸 수 | 사용하지 않는 칸 (선택, 쉼표로 구분) |
   |---|---|---|
   | 3학년 1반 | 28 | |
   | 3학년 2반 | 30 | 15, 16 |

   - 사용하는 칸 수가 28이면 **29~33번은 자동으로 "미사용"** 칸이 됩니다. 점검 화면에 점선으로 표시되고, 사유를 묻지 않으며, 대시보드 통계에서도 빠집니다.
   - 중간에 늘 비어 있는 칸이 있으면 세 번째 열에 번호를 적습니다.
   - 반이 하나뿐이라면 한 줄만 적으면 됩니다. 이때는 학생 시트의 반 칸이 비어 있어도 됩니다.
4. **학생** 탭에 학생 학교 이메일과 이름을 입력하고, **반** 칸에는 보관함 탭에 적은 이름을 **똑같이** 적습니다. 이번 당번인 학생은 당번 칸에 `O`를 적습니다. 당번이 바뀌면 이 칸만 고치면 됩니다.
   - 반 이름이 보관함 탭과 다르면 점검 화면에 "보관함 시트에 ○○ 반이 없습니다"라고 나옵니다.
5. **교사** 탭에 선생님 이메일을 넣습니다.

> 이미 설치해서 쓰고 있다면: 새 `Code.gs`와 `Index.html`을 붙여 넣고 **setup을 한 번 더 실행**하세요. 기존 데이터는 지워지지 않고, 보관함 탭이 새로 생기며 학생 탭에 반, 번호 머리글이 추가됩니다. setup을 안 해도 앱은 예전처럼 33칸짜리 보관함 하나로 동작합니다.

### 3. 사진 분석 키 넣기
1. aistudio.google.com 에서 학교 계정으로 **API 키**를 만듭니다.
2. Apps Script 프로젝트 설정 → **스크립트 속성 → 속성 추가**
   - 속성: `GEMINI_API_KEY` / 값: 방금 만든 키
3. (선택) 속성 `GEMINI_MODEL`에 AI 스튜디오에서 지금 쓸 수 있는 모델 이름을 넣습니다. 안 넣으면 `Code.gs`의 기본값을 씁니다. 이름이 바뀌었으면 분석이 실패하니 AI 스튜디오에서 확인해 주세요.

> 키는 스크립트 속성에만 넣습니다. 코드나 시트에 적지 마세요.

### 4. 배포
1. 오른쪽 위 **배포 → 새 배포 → 유형: 웹 앱**
2. 다음처럼 설정합니다.
   - 실행 사용자: **나**
   - 액세스 권한: **(학교 도메인) 내 모든 사용자**
3. **배포**를 누르고 권한을 허용합니다. 나오는 **웹 앱 URL**이 앱 주소입니다.
4. 이 주소를 QR코드로 만들어 충전기에 붙입니다.

### 5. 먼저 시험해 보기
1. 학생 탭에 **선생님 본인 이메일**을 당번 `O`로 넣고(교사 탭에도 있어야 선생님 화면이 보입니다), 웹 앱 URL을 엽니다.
2. 먼저 `test-photos/cart-sample-01.jpg`(시험용 사진)를 올려 보고, 같은 폴더의 `cart-sample-01.answer.json` 정답표와 비교합니다. 그다음 실제 보관함 사진을 올려 보고, **33칸 결과가 맞는지** 확인합니다. 틀린 칸이 많으면 알려 주세요. 지침을 고칩니다.
3. 제출해서 점검기록과 코인내역 탭에 행이 생기는지 봅니다.
4. 시험이 끝나면 시험 행은 지우고, 본인 이름은 당번에서 뺍니다.

## 코드 업데이트 자동화 (clasp, 선택)
코드가 바뀔 때마다 붙여 넣고 새 버전을 배포하는 대신, **명령 한 줄**로 올릴 수 있습니다. 한 번만 설정하면 됩니다.
웹 앱 주소(QR코드)는 바뀌지 않습니다.

### 처음 한 번만
1. **Node.js 20 이상**을 설치합니다(nodejs.org).
2. 이 저장소를 받고 폴더에서 설치합니다.
   ```bash
   git clone https://github.com/SonYoungguk/chromebook-check-app
   cd chromebook-check-app
   npm install
   ```
3. 브라우저에서 script.google.com/home/usersettings 를 열어 **Google Apps Script API**를 **켭니다.**
4. 학교 계정으로 로그인합니다.
   ```bash
   npm run login
   ```
5. **스크립트 ID**를 연결합니다. Apps Script 왼쪽 톱니바퀴(프로젝트 설정)의 **ID**를 복사하고, `.clasp.json.example`을 `.clasp.json`으로 복사한 뒤 `scriptId` 값에 붙여 넣습니다.
6. **배포 ID**를 저장합니다. Apps Script의 **배포 → 배포 관리**에서 웹 앱 배포의 ID를 복사해 `.deployment-id` 파일에 한 줄로 저장합니다. 또는 `npm run release`를 한 번 실행하면 배포 목록이 나옵니다. `@HEAD`는 테스트용이라 쓰지 않습니다.

`.clasp.json`과 `.deployment-id`는 `.gitignore`에 들어 있어 GitHub에 올라가지 않습니다.

### 코드를 고칠 때마다
```bash
git pull
npm run release
```
`release`는 코드를 앱스 스크립트에 올리고, 기존 웹 앱 배포를 새 버전으로 갱신합니다.
코드만 올리고 배포는 나중에 하려면 `npm run push`를 씁니다.

### 알아 둘 점
- 올릴 때 앱스 스크립트 쪽 파일은 `Code.gs`, `Index.html`, `appsscript.json`으로 **통째로 덮어써집니다.** 편집기에서 직접 고친 내용이나 `코드.gs` 같은 기존 파일은 사라지므로, 코드는 저장소에서만 고치세요.
- 스크립트 속성(`GEMINI_API_KEY`)과 시트 데이터는 건드리지 않습니다.
- 학교 구글 관리자가 앱스 스크립트 API나 외부 앱 로그인을 막아 두었으면 3~4번 단계에서 실패합니다. 이 경우에는 기존처럼 붙여 넣고 **배포 → 배포 관리 → 새 버전**으로 올리면 됩니다.

## 운영

### 코인 규칙 (Code.gs 위쪽 `CONFIG`에서 바꿉니다)
- 아침, 방과 후 각 1회만 코인을 줍니다. 같은 시간대에 다시 제출하면 코인이 없습니다.
- 코인은 서버에서 1~5개를 뽑습니다. 확률은 1개 35%, 2개 30%, 3개 20%, 4개 10%, 5개 5%입니다. 학생 화면에서는 조작할 수 없습니다.
- 제출하면 뒤집어진 카드가 나오고, 학생이 카드를 눌러 뒤집으면 코인 수가 보입니다. 코인은 제출 시점에 서버에서 이미 정해져 기록됩니다.
- 사진 분석을 거친 제출만 코인을 줍니다(`REQUIRE_AI_FOR_COIN`).
- 코인 확률은 `COIN_TABLE`의 가중치로 바꿉니다.

### 선생님 대시보드
교사 탭에 이메일이 있는 계정으로 웹 앱을 열면 **선생님** 탭이 보입니다. 위쪽에서 **보관함(반)** 과 7일, 30일, 전체 기간을 고를 수 있습니다. 반이 둘 이상이면 맨 위에 **오늘 반별 제출** 현황이 나와 어느 반이 아직 제출하지 않았는지 한눈에 볼 수 있습니다.

| 영역 | 보여 주는 것 |
|---|---|
| 요약 4칸 | 오늘 제출 여부, 마지막 점검의 빈 칸 수, 평일 기준 제출률, 학생이 AI 판정을 평균 몇 칸 고쳤는지 |
| 가장 최근 보관함 | 마지막으로 제출된 33칸 상태와 빈 칸의 사유 |
| 자주 비는 칸 | 33칸 각각이 기간 내 점검에서 비어 있던 비율(진할수록 자주 빔)과 TOP 5, 주된 사유 |
| 비어 있던 이유 | 사유별 횟수 |
| 날짜별 제출 현황 | 날짜 × 아침/방과 후 표. 평일 미제출이 바로 보입니다 |
| 학생별 | 기간 내 제출 횟수, 받은 코인, 현재 코인 |
| 제출 기록 | 최근 20건. 눌러서 펼치면 그날의 33칸 상태 |

- 칸이나 막대에 마우스를 올리면(폰에서는 누르면) 자세한 숫자가 보입니다.
- 서버가 최근 600건까지 한 번에 보내고, 기간은 화면에서 걸러 보여 줍니다.
- 학생이 고친 칸 수가 계속 크면 AI 판정이 자주 틀리거나 학생이 확인 없이 제출한다는 신호입니다.
- 같은 기록은 구글 시트의 `점검기록` 탭에서도 직접 볼 수 있습니다.

### 보상 교환
- 선생님 화면의 **코인 사용 처리**에서 학생, 코인 수, 메모를 입력하면 차감됩니다.
- 시트의 **코인내역** 탭에 음수 행으로 남아 기록이 지워지지 않습니다.
- 잘못 지급하거나 차감했으면 코인내역 탭에 반대 부호 행을 추가해 바로잡습니다.

### 꼭 지킬 것
- 구글 시트를 **학생과 공유하지 마세요.** 학생은 앱으로만 접근해야 합니다.
- 코드를 고치면 **배포 → 배포 관리 → 새 버전**으로 다시 배포해야 반영됩니다.
- 학생이 명단에 없으면 "명단에 없는 계정입니다"라고 나옵니다. 이메일 철자를 확인하세요.

## 문제 해결
| 증상 | 확인할 것 |
|---|---|
| 열었는데 "로그인 정보를 확인할 수 없습니다" | 배포 액세스가 "도메인 내 모든 사용자"인지, 학교 계정으로 로그인했는지 |
| 사진 분석이 늘 실패 | 스크립트 속성 키, 모델 이름. 편집기 왼쪽 **실행 기록**에서 `Gemini HTTP` 오류를 봅니다 |
| 외부 요청 권한 오류 | 학교 구글 관리자가 앱스 스크립트의 외부 요청을 막았을 수 있습니다 |
| 코인이 안 나옴 | 이미 그 시간대 코인이 지급됐거나, 사진 분석 없이 제출했는지 |

## 무료로만 쓰기 (비용 막기)
- AI 스튜디오 키가 **결제 계정이 연결되지 않은 무료 사용량**이면, 한도를 넘어도 돈이 나가지 않고 요청이 거절(429)될 뿐입니다. 구글 클라우드나 AI 스튜디오에서 **결제(빌링)를 연결하지 마세요.** 이미 연결했다면 해당 프로젝트의 결제 계정 연결을 해제하세요.
- 무료 사용량의 하루·분당 한도는 모델마다 다르고 바뀔 수 있으니 AI 스튜디오의 사용량(Rate limit) 화면에서 확인하세요.
- 앱에도 안전장치가 있습니다. `Code.gs` 위쪽 `CONFIG`에서 바꿀 수 있습니다.

| 설정 | 기본값 | 뜻 |
|---|---|---|
| `MAX_GEMINI_CALLS_PER_DAY` | 150 | 앱 전체가 하루에 Gemini에 보낼 수 있는 요청 수 (실패한 요청 포함) |
| `MAX_CALLS_PER_PHOTO` | 6 | 사진 한 장을 분석하려고 다시 시도하거나 다른 모델을 써 볼 수 있는 최대 횟수 |
| `MAX_SECONDS_PER_PHOTO` | 60 | 사진 한 장의 분석에 쓸 최대 시간(초). 넘으면 더 시도하지 않고 직접 표시로 넘어갑니다 |
| `MAX_ANALYZE_PER_HOUR` | 20 | 한 학생이 한 시간에 분석에 성공할 수 있는 횟수 (교사는 제한 없음) |

- 하루 상한에 닿으면 "오늘 사진 분석 횟수를 모두 썼습니다"라고 안내하고, 학생은 직접 표시로 제출할 수 있습니다(코인은 `REQUIRE_AI_FOR_COIN` 설정에 따름).
- 쓰던 모델이 바쁘거나(503) 없으면(404) 앱이 모델 목록에서 **다른 flash 계열 모델**을 골라 자동으로 시도합니다. 모델마다 무료 한도가 따로 있습니다.
